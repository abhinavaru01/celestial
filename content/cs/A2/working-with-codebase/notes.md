# Working with a Codebase

> [!intro] Reading unfamiliar code, git collaboration workflows, and code review.

## Reading code

Most professional work is reading and modifying existing code, not writing from scratch. Skimming structure, following functions, and running it build understanding.

## Collaboration

Teams use branches, pull requests and code review to change code safely. Review catches bugs and shares knowledge — a social skill as much as technical.

```formula Key syntax & rules
Read/understand before changing
Branch → pull request → review
Review for correctness and clarity, kindly
```

> [!example] **Worked example**
> **Problem.** What is the safe workflow to change a shared codebase?
> >
> > **Solution.** Create a branch, make the change, open a pull request, get it reviewed, then merge — never commit risky changes straight to main.

## What you should be able to do

- Read and navigate unfamiliar code
- Use branch-based collaboration
- Give and receive code review
