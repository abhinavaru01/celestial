# JEE Strategy Guide (Sample)

> Part of the **optional** competitive track. Designed to *overlay* the core timeline, not extend it — you practise on topics you've already mastered, replacing generic revision with exam-targeted work.

## What makes JEE hard (and how the core curriculum already prepares you)
1. **Multi-concept problems.** A single question fuses (say) kinematics + calculus + algebra. → The core curriculum's **interleaving and gate exams with transfer items** train exactly this from Foundation onward.
2. **Non-standard framings.** Familiar physics dressed in unfamiliar setups. → **Level-3 quizzes** on every topic drill transfer, not recall.
3. **Speed.** ~2 minutes per question. → Core **fluency (Level-2)** builds automaticity; this guide's shortcuts do the rest.
4. **Depth of traps.** Wrong options are engineered from common errors. → Each topic's **Common Mistakes** layer *is* the trap catalog.

## Prep calendar (overlay model)
- **During I1–I2:** attempt JEE-Main-entry sets for each topic *as you master it*. ~2–3 hrs/week, replacing generic revision.
- **During A1–A2:** shift to standard and hard sets; begin timed sections. ~4–5 hrs/week.
- **Post-A2 (months, not years):** full-length timed mocks + PYQ analysis. This is the window a conventional path spends in separate multi-year coaching — you have it "to spare" because the core finished early.

## Exam-day method (the four-pass sweep)
1. **Pass 1:** solve everything you can in <90s. Bank easy marks.
2. **Pass 2:** return to medium questions needing 2–3 minutes.
3. **Pass 3:** attempt hard questions only if time and marking scheme favour it.
4. **Pass 4:** review flagged answers; check units and sign conventions (the cheapest marks to lose).

## Highest-leverage shortcuts (from the core Tricks layers)
- Average of rates → **harmonic mean / total-over-total**, never the arithmetic mean.
- Percentage change → **chain multipliers**; reverse → **divide by the multiplier**.
- Constant-acceleration ratios → **s ∝ t² from rest**; derive forgotten equations from the **v–t graph**.
- Always **estimate first** to catch decimal-slip errors — a habit built in the very first math topic.
